# 폭풍을 걷는 도시

멸망하는 세계에서 이동식 도시를 조립하는 한국어 2D 전략 로그라이크입니다. **공격 예고를 읽고 도시의 배치로 받아낸 뒤, 피격 에너지를 반격으로 전환**합니다. Canvas 전장과 DOM 메뉴, 순수 TypeScript 규칙으로 구현했습니다. 외부 게임의 캐릭터·이미지·음악을 사용하지 않습니다.

## 실행

Node.js 22.12 이상(검증 환경: 24.12), npm이 필요합니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 `http://127.0.0.1:5173/`을 브라우저에서 엽니다.

```sh
npm test          # 규칙, 전체 캠페인, DOM 조작 검증
npm run typecheck # TypeScript 검사
npm run build     # dist/ 정적 배포 파일 생성
npm run preview   # 빌드한 파일 미리보기
npm run standalone # outputs/stormwalker.html 단일 파일 생성 (먼저 build)
```

단일 HTML은 외부 이미지·폰트·서버 없이 열 수 있습니다. 안정적인 저장 슬롯은 같은 브라우저와 같은 주소의 개발/정적 서버 사용을 권장합니다. 브라우저가 저장 공간을 차단하면 오류를 표시하며 현재 게임을 유지합니다.

## 플레이

1. 시드를 입력하고 새 여정을 시작합니다.
2. 정비 단계에서 부품을 선택해 빈 칸에 조립합니다. 기존 부품을 선택하면 이동, 회전, 판매, 수리할 수 있습니다.
3. 배치를 확정하고 적의 의도를 읽습니다. 매 턴 인접 이동·회전·우선순위 변경·긴급 수리 중 지휘 행동 2회를 사용합니다. 아무 행동 없이 실행해도 됩니다.
4. **결과 예측**으로 실제 실행과 같은 계산 결과, 견인 후 공격선, 전력 수지를 확인합니다. 지휘는 실행 전 한 번씩 또는 전체 취소할 수 있습니다.
5. 실행 후에는 되돌릴 수 없습니다. 전투 승리 시 고철과 세 보상 중 하나를 얻고 다음 정비로 이동합니다.
6. 2·4번째 조우 이후 안전한 방풍 터널 또는 고철이 풍부한 폐철 고원을 선택합니다. 6번째 조우의 문지기를 처치하면 승리합니다. 핵이 파괴되면 패배하며 재시작할 수 있습니다.

첫 전투는 기본 배치 그대로 3턴에 돌파할 수 있습니다. 첫 턴은 방벽 피격 → 폭풍 유리 전력 +5 → 축전기 충전 → 대포 반격을 보여줍니다. 이후에는 적의 공격 열에 맞춘 대포와 방벽을 추가하고, 파괴된 방벽을 재조립하세요.

키보드: Canvas에 Tab으로 진입, 방향키로 칸 이동, Enter로 선택·배치, R 회전, M 이동, Escape 취소. 터치와 마우스 클릭을 지원합니다. 소리는 사용자 버튼으로 켜는 자체 합성 효과음입니다.

## 규칙

- 도시 좌표는 `(x,y) = 0…6`입니다. 화면의 A–G열, 1–7행과 대응합니다. 북/남 외곽 적은 `(x,-1)/(x,7)`, 서/동 외곽 적은 `(-1,y)/(7,y)`에 있습니다. 모서리는 적의 유효 위치가 아닙니다.
- 적은 외곽에서 안쪽으로 직선을 만들고 **첫 생존 부품**에 피해를 줍니다. 범위 공격은 중심과 ±1의 3개 선입니다. 보스의 교차 공격은 양쪽에서 들어옵니다.
- 대포는 지정 방향·같은 행 또는 열의 가장 가까운 적을 공격하며 아군을 관통합니다. 견인기는 맨해튼 사거리 안의 가장 가까운 유효 적을 화살표 방향의 빈 외곽 칸으로 1칸 옮깁니다. 그 뒤 적 공격선을 다시 계산합니다.
- 직교 인접하고 단선되지 않은 부품이 하나의 전력망을 만듭니다. 발전기만 매 턴 기본 전력을 생산합니다. 발전기가 없는 망도 축전기에 남아 있는 전력은 소비할 수 있습니다. 피격 발전 유물은 발전기가 연결된 망에서만 작동합니다.
- 생산 전력은 발전기 위치, 이전 저장은 축전기 위치에 놓입니다. 소비할 때 현재 연결망에서만 가져옵니다. 연결 다리가 파괴되면 그 순간부터 서로 전력을 나눌 수 없습니다. 파괴된 전원에 남은 전력은 손실됩니다.
- 전력 소비는 `P1 → P2 → P3`, 동순위는 안정적인 부품 ID 순입니다. 현재 유효한 소비 부품에 우선권을 배정한 뒤 단계 순으로 실행합니다. 과열·대상 부재·단선·전력 부족 사유를 선택 창에 표시합니다.
- `시작 저장 + 생산 + 피격 발전 = 소비 + 종료 저장 + 손실`. 전력 수지는 실행 시작 때의 연결망을 기준으로 추적합니다. 사용하지 않은 전력은 살아 있는 축전기의 용량까지만 저장하며 넘치는 전력은 손실됩니다. 단선된 기존 축전 전력은 잠겨 보존되지만 그 턴에 들어온 미저장 에너지는 남은 연결망에서 사용할 수 없습니다.
- 발전 → 견인 → 적 공격·피격 효과 → 살아 있는 대포 공격 → 냉각·수리·회수 → 자연 냉각·축전 정산 → 승패·다음 의도 순으로 진행합니다. 핵 파괴가 동시 적 전멸보다 우선합니다.
- 단선탄은 피격 부품을 현재 턴의 남은 단계와 다음 턴에 분리합니다. 자연 냉각은 턴당 1입니다. 대포는 발사 시 열 +3, 실행 시 열 8 이상이면 정지합니다.
- 적 잔해는 가장 가까운 도시 가장자리 칸에 생깁니다. 회수기 범위 안의 잔해는 전부 고철로, 승리 후 남은 잔해는 총량의 절반만 회수합니다.
- 6개 유물의 발동 시점과 턴당 예산은 `content.ts`에 정의합니다. 유물 효과는 다른 유물 이벤트를 재귀 호출하지 않습니다. 폭풍 유리는 살아남은 방벽에만 발동합니다. 서리 화약은 실제로 제거한 열만 최대 총 6, 대포당 최대 4를 다음 공격으로 옮깁니다.
- 보스는 정면 3열 공격으로 시작하고 체력 절반 이하에서 동쪽으로 이동하여 연결 방해와 동서 교차 공격을 번갈아 예고합니다.

## 구성

`src/content.ts` 데이터 / `state.ts` 상태 / `grid.ts` 좌표 / `power.ts` 연결·우선순위 / `effects.ts` 유물 예산 / `combat.ts` 순수 전투 / `campaign.ts` 조우·경로·보상 / `rng.ts` 시드 난수 / `actions.ts` 지휘 / `save.ts` 저장 검증 / `ui/board.ts` Canvas 렌더 / `main.ts` DOM 화면과 입력.

`resolveTurn`은 입력을 변경하지 않고 다음 상태·사건·전력 수지·작동 사유를 반환합니다. UI의 미리보기와 실제 실행이 같은 함수를 호출합니다. 연출 중에는 입력을 잠그고 계산 결과를 한 번만 확정합니다. 게임 난수는 자체 xorshift32만 사용하며 장식은 게임 난수를 소비하지 않습니다.

저장 버전은 1입니다. 정비·보상·경로·종료 또는 지휘 계획이 없는 턴 경계에서만 수동 저장합니다. 읽기 시 모든 주요 필드, 좌표, ID, 중복, 수치 범위, 핵 존재와 단계 조건을 검증합니다. 손상 데이터나 미지원 버전은 기존 진행을 덮어쓰지 않습니다.

## 검증 기록

- 규칙 테스트 35개: 요청된 충돌·사거리·전력·견인·유물·결정성·저장·승패 검증 포함.
- 캠페인 통합 테스트 1개: 자원이나 피해를 주입하지 않고 실제 구입·수리·배치로 6개 조우와 두 경로 선택, 보스 두 단계, 승리까지 진행합니다. 각 턴의 전력 보존과 저장 복원도 검사합니다.
- DOM 통합 테스트 1개: 시작, 조립, 판매, 계획 취소, 예측, 중복 실행 방지, 전투, 보상, 저장, 로드, 재시작. Canvas 그리기만 대체하며 실제 규칙·입력 처리·저장은 사용합니다.
- TypeScript 검사, Vite 배포 빌드 성공.
- 실제 브라우저의 개발 서버 접근은 `ERR_CONNECTION_TIMED_OUT`으로 차단되어 시각·터치·오디오 QA는 미완료입니다. DOM 테스트를 실제 브라우저 검증으로 간주하지 않습니다.

첫 버전의 다음 검증 과제는 피격 발전을 의도적으로 선택할 유인이 충분한지, 방벽을 유지할지 이동시킬지의 판단이 읽히는지, 보스의 측면 전환이 예측 가능한 도전인지입니다. 다양한 시드·위험 경로·유물 조합의 전체 밸런스는 추가 플레이테스트가 필요합니다.
